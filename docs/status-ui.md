# 查看任务、会话与系统状态

Jarvis Box 在同一服务提供终端工作台、状态页和产品文档：在终端工作台处理工作，在状态页查看交付统计和维护系统，在文档中查阅使用方法。本文面向日常使用者和负责这套部署的运维人员；接口调用方式见 [Status API](status-api.md)。

将下表路径接在你的 Jarvis Box 服务地址后。例如本机默认服务的终端入口为 `http://127.0.0.1:8787/status/terminal`。

| 入口 | 用途 |
| --- | --- |
| `/status/terminal` | 新建或选择任务，查看连续会话，补充要求，停止执行，查看文件 |
| `/status` | 查看运行与交付统计，修改接入配置，诊断和维护系统 |
| `/docs/` | 阅读随本实例交付的产品文档，支持本地搜索 |
| `/test-coverage` | 查阅业务能力清单和已登记的实现缺口 |

这些页面属于同一可信团队的管理入口。需要远程访问时，先按 [网络入口](network-ingress.md) 配置访问保护；不要把管理页面直接暴露到公共网络。任务文件内容与工作目录浏览只接受本机 loopback 请求，上游网关认证不能替代这个限制。

## 终端工作台

终端工作台呈现 Agent 的会话与工具输出，并提供任务操作；它不是可直接输入系统命令的 Shell。任务是一项持续的工作，运行是 Agent 对这项工作的一次执行。同一任务可以有多次运行，补充要求时通常继续原任务即可。

### 新建任务

1. 打开 `/status/terminal`，点击右上角“新建任务”，或按 `Ctrl + Shift + Enter`（Mac 同样使用 Control）。无需先打开任务选择器。
2. 填写要求和“任务归属”，归属可选择已有建议或填写新名称。归属用于显示和分组，不会替用户登录其他平台或授予身份。
3. 按需选择本次使用的智能体，点击“创建并打开会话”。
4. 在打开的会话中查看进展与回复，继续输入补充要求。

当前浏览器会记住上次填写的有效归属，刷新后仍可沿用；从归属组新建或筛选了具体归属时，优先预填该归属。仅打开或取消表单不会改变记忆；实际编辑或创建成功后才更新，中文输入法组词期间不保存中间文字。清空输入可移除记忆，无效输入不会覆盖最近有效归属；浏览器禁用站点存储时仍可正常新建。

单次智能体选择不修改系统默认值。创建失败时保留草稿和选择，按页面原因修正后再提交。系统状态尚未读取或不可读取时，发送操作暂不可用，草稿仍可编辑。

### 找到已有任务

点击顶部任务入口，或按 `Command/Ctrl + K` 打开同一个任务选择器。可以按显示标题、归属、来源筛选，也可以输入完整任务编号或运行编号查找。切换筛选后从顶部读取新结果。首次读取失败时显示重试提示，列表与计数在新查询成功后更新。列表、选中后的标题和悬浮说明使用同一个脱敏标题；辅助名称以该标题开头，并读出行内的状态、智能体、来源和活动时间，便于区分同名任务。过长的来源标题或请求使用有长度限制的摘录；完整来源标题仍可搜索，正文保留原始请求。显示宽度造成的省略不再缩短搜索范围。

任务最初使用来源事项标题或原始请求作为名称。某次执行稳定结算后，优先采用经过核验的智能体会话名称；缺少时，系统可由独立的普通 `task-recap` 工作生成简短概括。这个后台工作使用为任务概括配置的默认智能体，失败、取消或不可用时保留已有名称；确实没有可用材料时显示“未命名任务”和短编号。继续运行期间保留原名称，符合当前来源 Run 的新概括就绪后自动更新，不改变草稿或任务排序。概括任务使用原始任务材料，需要补充指令时请在原任务发送。概括不会改写来源事项标题，也不推断“已修复”等执行结果。打开历史记录、升级或刷新页面不会为历史任务启动概括工作。

目录先给出最近任务的预览；需要浏览更多时加载完整列表。排序依据任务的业务活动，编辑工作目录文件不会把任务重新置顶。没有运行记录的任务仍可选择，页面会说明等待原因和可用操作。

选中任务后，正文按执行顺序展示各次运行。运行分界和任务资料中可查看运行状态、智能体、时间和完整编号。打开历史运行只改变浏览位置，不会重新执行它。

### 补充要求与停止

在输入区发送后续要求即可继续这项工作。`Enter` 发送，`Shift + Enter` 换行。选择本次智能体只影响下一次执行。

- 正在执行时提交新要求，会中断旧运行，再按新要求接续。页面显示受理或等待期间，不必重复发送。
- 点击停止会结束当前执行，任务、已有记录和工作目录仍保留。需要继续时，再提交后续要求。
- 浏览历史运行时，普通继续操作仍作用于任务当前进度，不以历史输出为起点重放工作。
- 临时切换任务时，各任务未发送的输入和智能体选择分别保留。不要把未发送草稿当成已经提交或已经备份的任务记录。

出现需要回答的问题时，在原 IM 会话回答；网页不会因为能查看问题就获得代答权限。具体问题和回答方式见 [IM 使用说明](integrations/im.md)。

### 阅读长会话与查看文件

会话会逐步读取前后记录。向上翻阅时暂停跟随，新回复不会抢走阅读位置；回到最新位置后恢复跟随。工具输出先显示短预览，展开可读完整内容。较大的记录首次准备可能需要更多时间，读取持续推进时会自动继续；连续 30 秒没有进展时暂停自动读取，可点击“查看最新记录”重试。读取失败、历史缺失和只读内容会单独说明，不把尚未读取的运行当成没有输出。

用户消息附带的完整运行环境说明默认折叠，展开仍可查看原文。启动失败时，对应运行显示已保留的指令和脱敏后的错误详情。用户原始要求、代码和智能体回复保持原意。

文件入口区分两类内容：**所选运行的产出**和**任务当前工作目录**。选择历史运行不会恢复历史工作目录。标题更新时保留已选运行；任务资料读取失败会结束加载提示，可点击“重新读取任务详情”恢复查看。目录已清理时显示记录，不能把路径记录当成文件仍然存在。文件内容与工作目录浏览受前述本机访问限制。

| 需要做的事 | 操作 |
| --- | --- |
| 新建任务 | 右上角“新建任务”，或 `Ctrl + Shift + Enter` |
| 切换任务 | 顶部任务入口，或 `Command/Ctrl + K` |
| 继续当前工作 | 在输入区发送后续要求 |
| 阅读工具完整输出 | 展开对应工具记录 |
| 查找运行编号 | 展开任务资料或查看运行分界 |
| 保持阅读历史 | 向上滚动；回到最新后恢复跟随 |

### 发送失败或结果未知

页面只显示当前任务实际允许的恢复操作。

- 出现“重试发送”时，可重发已经生成的结果，无需重新让 Agent 做一遍工作。
- 结果是否送达未知时，先到接收方核实。若页面提供确认操作，选择“确认已送达”结束等待；选择“确认未送达并重试”会重新发送。
- 不存在确认或重试入口时，按具体原因处理，不要仅凭卡片外观推断结果，也不要反复继续来重发同一份产出。

IM 详情链接可以定位指定任务和运行。链接只用于查看，打开它不会启动、继续或停止工作。指定记录不可读取时会提示原因；从状态页进入“终端工作台”可继续查看所选记录。

## 使用状态页

`/status` 显示交付成果和系统设置两个窗口，初次打开面向交付成果。任务操作使用顶部“终端工作台”入口；“产品文档”在新标签中打开本实例的 `/docs/`，保留当前工作台。

| 操作 | 效果 |
| --- | --- |
| 按住空白或面板外框拖动 | 调整观看方向 |
| 横向滚动，或 `Shift + 纵向滚轮` | 左右转向 |
| 在空白处纵向滚动 | 调整观看距离，范围为 60%–120% |
| `Home` / `End` | 面向交付成果 / 系统设置 |
| `Escape` | 从设置返回交付成果，或退出仅显示背景 |
| “重置视角” | 恢复水平视线和 100% 观看比例 |

内容区的滚动优先用于阅读，不会在滚到底部后突然缩放页面。浏览器自身的缩放快捷键照常工作。首次操作指引可关闭，也可从“操作指引”重新打开。页面面向桌面使用。

时间标签按浏览器时区以 24 小时制显示。原始日志和文件中的时间保持原文；每日、每小时统计采用浏览器提供的时区，无法确认时区时显示不可用。

## 累计产出与交付质量

交付成果汇总本机执行记录，以及已接入 GitLab、GitHub 的交付分析。标题旁的 ⓘ 解释统计范围；点击或按 `Enter`、空格打开，点击外部或按 `Escape` 关闭。

### 本机运行统计

八项指标分别是累计受理记录、今日执行次数、昨日执行次数、累计执行次数、累计执行时长、日均执行（去异常）、平均任务处理时长和任务处理时长中位数。

- 累计受理与执行统计来自历史账本，不等于当前保留的任务数量。清理旧任务记录不会将累计统计归零。
- 执行耗时统计已结束的运行，包含失败或取消的运行；等待、两次运行之间的间隔和仍在执行的时间不冒充已完成耗时。
- `0` 表示已确认没有记录或耗时为零，`—` 表示无法确定，`≥` 表示只有已确认的下限。平均值和中位数使用已知样本，不把下限当成完整耗时。

每日趋势可选择时间范围、隐藏异常高峰；图中的线性趋势描述已有记录，不预测未来。筛选不改变累计指标和其他图表的统计范围。

“按小时 Run 启动分布”展示一天 24 个时段的启动次数，分别给出跨完整自然日的平均值和中位数。它不表示运行时长、同时在线的 Agent 数量或 CPU 利用率。只统计已核验覆盖范围内的完整浏览器时区自然日，不含覆盖边界日和今天。没有完整样本与确认零次不同，页面会说明原因。

### 代码交付与账号活动

GitLab、GitHub 各自独立统计当前运行账号的代码交付，不把不同平台的数量混成一个验收结论。

| 显示内容 | 应怎样理解 |
| --- | --- |
| 已合并 | 代码变更已合并，不等于客户业务验收通过 |
| 未发现人工纠正 | 在可分析记录中未发现他人的实质纠正，不等于证明完全无人参与 |
| 发现人工纠正 | 他人的实质反馈促成了修改；普通批准、同步主分支或机器人转述不单独算纠正 |
| 分析覆盖、待分析、无法判断 | 说明分析范围和缺口，未知项不能当成零或成功 |
| 账号活动热力图 | 该平台账号的可见活动，可能包括 Jarvis 之外的工作，不等于 Jarvis 独立交付量 |

GitLab 和 GitHub 的交付质量卡各有一个默认关闭的「排除自我改进和回迁」按钮。打开后，当前账号的三项指标和仓库明细使用相同的筛选范围。卡片显示已排除的自我改进、回迁和来源待复核数量。来源待复核的记录暂计入。配置仓库的全账号合并数、分析覆盖和待分析数仍使用全量口径。旧快照尚无筛选数据时继续显示全量指标。

热力图保留平台原生日期，未知日期单独标记。代码交付的仓库范围与账号全年活动范围不同，不能直接互算比例。

### 工单自动修复与历史分析

自动修复图表按工单统计从接入到实际修复合并的阶段。同一工单的重试不变成多个工单；未知阶段或不完整来源保留缺口，不把一次运行成功当成修复已合并。完整口径见 [状态 API](status-api.md)。

历史分析在后台进行，关掉网页不会停止；刷新页面也不会另起一份分析。可在终端工作台查看对应分析任务的进展，按 [历史起点操作手册](delivery-metrics.md) 处理起点、恢复和重试。

## 系统设置

系统设置按要做的事分为五个区域：

| 区域 | 用途与影响 |
| --- | --- |
| 系统概览 | 查看健康、版本和授权；检查或安装软件更新 |
| 处理问题 | 查看诊断与恢复入口，重新连接消息渠道 |
| 工作方式 | 修改默认智能体、工作类型覆盖，查看模型与额度 |
| 接入配置 | 查看各来源缺少什么，保存下次启动使用的配置 |
| 数据维护 | 预览清理范围，清理符合条件的记录和工作文件 |

版本、路径、资源和授权详情可在“技术细节”中展开。容器内显示的资源不代表 Docker 宿主机的全部资源。

### 保存配置与重启

接入配置的“缺少配置”“部分配置待确认”“配置齐全”反映配置检查结果，**不代表平台连接、真实工作或通知送达已经验证**。接入后仍需按对应指南验证真实工作。

填写“修改为”并保存后，配置写入 `JARVIS_ENV_FILE`，下一次服务启动才生效。“当前生效值”仍显示正在运行的值。密钥输入框不会回填旧值，留空表示保留原值；保存前会备份，操作反馈提供恢复路径和命令。保存会检查支持的键与必要约束，但不等于已经完成下一次启动验证。

配置保存不打断任务。有活动工作时，页面会先请求确认。确认后，服务按[维护预检](operations.md#停止或重启-native-服务)检查能否安全暂停，服务恢复时会自动接续本次实际中断的任务。由 Docker 管理的实例应使用对应的部署入口。重新连接消息渠道只重建连接，不取消任务。

### 软件更新

系统概览可检查稳定版并预先下载。下载期间任务继续；准备好后，“更新并重启”会说明中断和恢复范围，确认后按本次维护清单自动接续符合条件的任务。

若复核发现更高版本，需要对新候选重新确认。更新成功以实际运行版本匹配候选为准，旧服务仍能回应不代表更新已经完成。失败后按页面原因处理，不把失败的安装重复当成已经确认的更新。

### 智能体、模型与额度

每次保存默认智能体都会清除所有智能体和工作类型的前置参数。需要自定义参数时，在保存后重新配置。默认智能体和工作类型设置适用于保存后新启动的运行。

某个工作类型切换到不同智能体时，会清除该工作类型的前置参数。重复保存当前使用的智能体会保留参数。选择“使用默认”会移除该工作类型的单独设置及其前置参数。

模型资源与额度按“智能体 → 目标模型 → 计费方／账户 → 额度证据”显示。多个智能体可能共用同一个脱敏账户引用；命令能运行不代表账户有余额，额度读取失败也不单独阻断已有任务。平台没有公开、安全的额度接口时会显示暂不支持读取；接入方式不明确时会说明原因，不猜测可用余额或计费方。

### 授权与数据维护

授权详情与 `jarvis-box license status` 使用相同事实。不能新建运行或最近签到失败时，系统概览会突出原因；“重新检查”对在线授权执行签到，对离线授权执行本地验签。

临近到期提醒和版本升级建议本身不表示系统故障。到期提醒按离线授权的租约截止、在线授权的合同截止计算；是否允许运行仍以当前授权判定为准。详情会说明需要续签合同还是重新获取离线文件。

“预览清理范围”不删除数据。“永久清理记录”只处理超过保留期限、已结束且工作文件夹已清理的任务。删除记录或工作文件无法撤销，操作前先确认保留和备份范围；活动任务、正在运行的 Agent、服务日志和依赖缓存不属于终态记录清理。

## 页面资源与定制

Status 的 HTML、CSS、JavaScript、图片和模型从磁盘读取，不内嵌在 `jarvis-box` 二进制中。`/status` 读取资源目录的 `status.html`，`/status/terminal` 读取 `terminal.html`，`/status/assets/<文件路径>` 读取该目录内的文件，支持自定义图片、字体和子目录，不提供目录列表，也不允许通过路径或符号链接读取目录外的文件。

产品文档的构建产物位于同一资源目录的 `docs/` 子目录，由 `/docs/` 提供；直接打开文档内页或刷新仍可阅读。文档只提供静态页面与资源，不提供目录列表或读取运行数据的入口。

Native 安装包根目录包含 `status_assets/`；安装后位于 `${JARVIS_STATE_DIR}/app/status_assets/`，服务以 `${JARVIS_STATE_DIR}/app` 为工作目录。未配置资源目录的直接 `serve` 进程读取当前工作目录下的 `status_assets/`。Docker 镜像默认通过 `JARVIS_STATUS_ASSETS_DIR` 指向 `/usr/local/share/jarvis-box/status_assets`。

每次 HTTP 请求都会重新读取文件，响应使用 `Cache-Control: no-store`。保存 HTML、CSS、JavaScript 或素材后刷新浏览器即可使用新版，无需重新编译、打包或重启服务；已打开的页面不会自动刷新。资源缺失时显示加载错误，不会回退到二进制里的旧页面，现有 API 仍由服务提供。

需要保留定制时，先复制同版本的完整资源目录到安装目录之外，并在当前 `JARVIS_ENV_FILE` 中配置 `JARVIS_STATUS_ASSETS_DIR` 为该目录的绝对路径。Native 示例使用实际部署的状态目录：

```bash
cp -R /absolute/runtime/state/app/status_assets /absolute/customer/status_assets
```

在环境文件中写入：

```dotenv
JARVIS_STATUS_ASSETS_DIR=/absolute/customer/status_assets
```

资源目录配置从下一次服务启动开始生效，按 [Native 运维流程](operations.md#停止或重启-native-服务)确认没有阻断任务后重启一次。以后只修改目录里的文件并刷新页面。升级会更新安装包拥有的默认资源，不修改外部自定义目录；客户负责在升级时将定制资源与目标版本的 API 和默认资源合并，并保留同版本完整的 `docs/` 子目录。

Docker 客户可在当前实例内把镜像的默认资源复制到持久目录 `/var/lib/jarvis-box/status_assets`，再在该 deployment 的 `runtime.env` 中设置 `JARVIS_STATUS_ASSETS_DIR=/var/lib/jarvis-box/status_assets`，通过 [Docker 部署流程](operations.md#升级)应用配置。宿主机对应目录为 `<deployment-home>/data/state/status_assets`，后续可以直接从宿主机编辑；容器只需读权限。不要在容器临时文件系统中保存需要保留的定制。

保留默认页面时，`status.js` 中的 `// __STATUS_INTEGRATIONS_EXTENSION__` 会在每次请求时插入同目录的 `status-integrations.js`；`/* __STATUS_PROVIDER_CATALOG__ */ {}` 会替换为服务端来源目录。两种标记最多各出现一次，完全自定义的脚本可以省略。`terminal-task-picker.js` 负责独立选择对话框；`terminal.js` 只使用相同的来源目录标记，不插入空间页的接入配置扩展；两页的单选菜单交互由 `hover-selects.js` 统一维护，箭头与内边距由 `hover-selects.css` 统一定义。终端与服务需整体匹配升级，缺少页面资源时提供返回状态页的链接。`status.html`、`status.js`、`terminal.html` 和 `terminal.js` 中的 `__BRAND__` / `__BRAND_UPPER__` 沿用助手显示名替换规则。自定义前端仍使用当前实例的 [Status API](status-api.md)和事件流。

资源目录是公开页面的组成部分，只放可公开给 Status 使用者的素材，勿放环境文件、凭据或运行数据。修改前保留资源备份；需要撤销时恢复备份文件并刷新浏览器。
