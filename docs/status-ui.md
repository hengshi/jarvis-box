# Status UI

`/status` 是 Jarvis Box 唯一的人类操作页，以第一人称空间工作台组织交付、工作与系统设置。四块持久玻璃面板从左到右依次为交付成果、工作项、对话、系统设置，初始面向交付成果，观看比例为 100%。面板悬浮在摄影背景前，背景随视角转动、俯仰和观看距离变化。左右滑动可连续转动视角，停在任意角度；Tab 进入面板或内部控件时，所属窗口自动移至正前方，必要时缩回 100% 以内以保证键盘焦点可见；面板边框仍可用方向键定位。身份附件两侧的悬浮按钮提示相邻面板方向。其他窗口保留空间位置，可部分位于视野之外。页面不提供全局标签或内容导航条。选择工作项会更新对话与任务资料，不自动转移视角。系统运维仍只有这一个入口。

工作项优先显示已有标题，缺少业务标题时使用真实来源和工作项编号，不推测任务诉求。标题最多显示三行，超出部分以省略号收起，悬浮提示保留完整原文。过长指令以真实来源或任务编号为标题、原文为三行预览，不自动生成摘要。对话资料栏的“当前工作”可展开完整标题。列表说明已加载及当前筛选显示的数量，关键词只搜索已加载工作；输入完整任务或运行编号可直接查找。无匹配结果时可清除搜索与全部筛选，有后续记录时可继续加载。空分类不额外占位。工作项面板只显示筛选与列表，不显示任务详情标题或分隔条；清理图标位于搜索框旁，保留明确提示和原有确认流程。

任务资料移到对话面板右侧，与左侧输出、输入区并列。元信息、同组任务历史与 Task / Run 记录共用一个资料滚动区域，长说明不会遮挡后续操作。任务与目录保持同一分组归属；同一工作项内切换或更新运行时保留资料滚动位置和任务展开状态。

四块面板均不显示外层标题或保留标题空行；所选运行的时间、智能体、状态和真实 ID 在右侧任务 / 运行分组中显示，输入区不重复展示。任务阻塞提示位于所属任务下，所选运行的失败原因位于对应运行下。输出 / 文件、消息筛选、滚动和跟随状态在同一行排列，输出摘要完整显示；窄宽度下可横向滚动。输出默认显示对话，切换“全部”可展开工具与运行记录；长输入可展开查看原文。资料栏标明当前查看的 Task，操作区显示下次使用的智能体。工作目录为 Task 的当前目录，运行产出属于所选 Run；已清理目录收为可展开的路径记录，并保留复制入口。

对话与工作项分别位于独立窗口，工作项在对话左侧，列表独占工作项面板，所选任务资料位于对话右侧栏。面板基础宽高按浏览器窗口计算，基础宽度最多占当前显示器逻辑宽度的 55%（以 `window.screen.width` 为准），浏览器全屏时仍保留这一上限；空白处纵向滚轮可调整观看距离，使面板和背景同步变近或变远。面向正面并停稳后，面板退出 3D 变换，使用原生布局缩放绘制文字。页面按桌面工作台设计，不提供手机专用布局。窗口内部独立滚动，任务详情、历史记录与输入区保持可访问。字体、轻边界与选中底色统一，同级标题和列表对齐。
任务尚未产生运行时，详情仍显示当前任务状态与可用操作，并明确“暂无运行记录”。等待、取消及后续首次启动随任务更新同步到列表、历史和详情，不依赖手动刷新；取消后不保留等待恢复提示或取消按钮。只有真实运行存在时才读取该运行的进展与输出。

历史起点的恢复和排障步骤见 [Delivery Metrics 历史起点操作手册](delivery-metrics.md)。

页面中的时间按浏览器所在时区以 24 小时制展示，包含任务与运行、进展与输出的时间标签、文件修改时间、系统检查、额度重置及授权日期；完整时间和悬浮提示同时标明时区偏移。到期提醒的日期由服务端提供的实际到期时刻转换，不使用服务器时区代替浏览器时区。时间格式化不改变排序、授权判断或已保存的时间；原始日志正文、文件内容以及不带时区的日期文本保留原文。

面板布局使用原生 CSS 透视与变换，摄影背景通过 CSS 透视与变换响应同一视角，不加载房间或设备模型。转向不重建面板，保留滚动位置、筛选和未提交输入。四块面板的内容始终可直接操作；点击工作项、输入、筛选、文件和设置控件不移动视角。对话窗口只显示所选任务的真实上下文，移除重复面板标题，四块面板本身保留可访问名称和键盘定位入口，不占用额外标题行。面板边框获焦后可用左右方向键转向，Home / End 面向最左 / 最右窗口。

按住背景或面板外框拖动，可左右转头、抬头或低头；各桌面平台使用相同交互，不显示视角滚动条。横向滑动连续控制左右朝向，Shift 加纵向滚轮也可转向。面板外框和空白处的纵向滚轮控制观看距离，对话、列表、文件与设置滚动区优先滚动内容，到达边界也不会接着缩放场景。按钮、链接、文本选择、输入框、选择器、弹窗、横向滚动内容及浏览器自身的缩放快捷键保持原生行为。悬浮附件中的“重置视角”面向最近窗口，恢复水平视线和 100% 观看比例；拖动和转向保留任务选择、滚动位置与未发送输入。

观看比例可在 60%–120% 之间调整，以面板按浏览器窗口计算的基础尺寸为 100%，与浏览器自身的页面缩放分别控制。

交付窗口使用大小卡片混排的瀑布布局：八项本机运行与积累指标各自成为 KPI 卡，数字突出显示，耗时单位使用较小字号，与各来源代码交付质量卡、工单自动修复进展、任务执行趋势及工作类型耗时明细共用同一网格。正常宽度下一排容纳四张 KPI 或两张大卡；各卡片高度随内容自然变化，后续卡片填入空位，较窄容器改为两张 KPI 或一张大卡。质量卡保留当前账号已合并、未发现人工纠正、发现人工纠正、分析覆盖、同步信息和分析进度，仓库明细常驻展示；各来源独立统计。图表范围、异常值开关和统计口径保持原有语义；切换趋势范围或异常值显示时，保留交付窗口的滚动位置与当前控件焦点。刷新统计位于上方悬浮附件，仅在面向交付成果时显示，内容统一纵向滚动。

首次打开页面显示操作指引，介绍空白处按住拖拽、左右滑动及上下滚轮。点击“开始工作”或按 Escape 后，当前浏览器记住完成状态；悬浮附件中的“操作指引”可随时重新打开。清除该站点的浏览器存储后会重新提示；存储不可用不影响页面操作。

页面采用统一的烟灰色磨砂材质，常驻面板使用约 30% 不透明度的底色与 75% 背景亮度，透出并柔化背后壁纸的明暗和颜色。没有桌子或设备模型，背景不表达业务状态，真实忙闲由工作快照和身份组件显示。悬浮附件中的“仅显示背景”暂时收起面板，再次点击或按 Escape 返回；视角、距离、任务选择与输入保持。

背景使用 39 张 macOS 默认壁纸的高清存档，来自独立的 [512 Pixels 图库](https://512pixels.net/projects/default-mac-wallpapers-in-5k/)，不是 Apple 官方托管服务；早期版本含存档提供的高清放大版本。通过 WordPress 图片 CDN 加载 3840px 宽的版本，原图链接保留在壁纸配置中。电脑本地时间 05:00–10:59 使用上午候选、11:00–14:59 日间、15:00–18:59 傍晚，其余为夜间；有明确晨昏版本时按时段选择，经典抽象壁纸按明暗分组，各时段分别有 22、19、26、20 张候选。

每个整点或手动“更换壁纸”时，从当前时段尚未看过的壁纸中随机选择，全部看完后再开始下一轮，并尽可能避开最近十张及当前壁纸。当前浏览器保存轮换进度，同一小时刷新复用已成功的图片。图片加载、解码及尺寸校验成功后才替换；失败保留当前背景和轮换进度，按钮可重试。摄影或抽象壁纸都随转头、抬头低头及观看距离同步移动和缩放，不读取电脑系统壁纸。

## 页面资源与定制

Status 的 HTML、CSS、JavaScript、图片和模型从磁盘读取，不内嵌在 `jarvis-box` 二进制中。`/status` 读取资源目录的 `status.html`，`/status/assets/<文件路径>` 读取该目录内的文件，支持自定义图片、字体和子目录，不提供目录列表，也不允许通过路径或符号链接读取目录外的文件。

Native 安装包根目录包含 `status_assets/`；安装后位于 `${JARVIS_STATE_DIR}/app/status_assets/`，服务以 `${JARVIS_STATE_DIR}/app` 为工作目录。未配置资源目录的直接 `serve` 进程读取当前工作目录下的 `status_assets/`。Docker 镜像默认通过 `JARVIS_STATUS_ASSETS_DIR` 指向 `/usr/local/share/jarvis-box/status_assets`。

每次 HTTP 请求都会重新读取文件，响应使用 `Cache-Control: no-store`。保存 HTML、CSS、JavaScript 或素材后刷新浏览器即可使用新版，无需重新编译、打包或重启服务；已打开的页面不会自动刷新。资源缺失时显示加载错误，不会回退到二进制里的旧页面，现有 API 仍由服务提供。

需要保留定制时，先复制同版本的完整资源目录到安装目录之外，并在当前 `JARVIS_ENV_FILE` 中配置 `JARVIS_STATUS_ASSETS_DIR` 为该目录的绝对路径。Native 示例使用实际部署的状态目录：

```bash
cp -R /absolute/runtime/state/app/status_assets /absolute/customer/status_assets
```

在环境文件中写入：

```dotenv
JARVIS_STATUS_ASSETS_DIR=/absolute/customer/status_assets
```

资源目录配置从下一次服务启动开始生效，按 [Native 运维流程](operations.md#停止或重启-native-服务)确认没有阻断任务后重启一次。以后只修改目录里的文件并刷新页面。升级会更新安装包拥有的默认资源，不修改外部自定义目录；客户负责在升级时将定制资源与目标版本的 API 和默认资源合并。

Docker 客户可在当前实例内把镜像的默认资源复制到持久目录 `/var/lib/jarvis-box/status_assets`，再在该 deployment 的 `runtime.env` 中设置 `JARVIS_STATUS_ASSETS_DIR=/var/lib/jarvis-box/status_assets`，通过 [Docker 部署流程](operations.md#升级)应用配置。宿主机对应目录为 `<deployment-home>/data/state/status_assets`，后续可以直接从宿主机编辑；容器只需读权限。不要在容器临时文件系统中保存需要保留的定制。

保留默认页面时，`status.js` 中的 `// __STATUS_INTEGRATIONS_EXTENSION__` 会在每次请求时插入同目录的 `status-integrations.js`；`/* __STATUS_PROVIDER_CATALOG__ */ {}` 会替换为服务端来源目录。两种标记最多各出现一次，完全自定义的脚本可以省略。`status.html` 和 `status.js` 中的 `__BRAND__` / `__BRAND_UPPER__` 沿用助手显示名替换规则。自定义前端仍使用当前实例的 [Status API](status-api.md)和事件流。

资源目录是公开页面的组成部分，只放可公开给 Status 使用者的素材，勿放环境文件、凭据或运行数据。修改前保留资源备份；需要撤销时恢复备份文件并刷新浏览器。

## 页面模型

交付成果同时展示已登录 GitLab / GitHub 账号最近一年的贡献热力图。各平台独立成卡，不受交付质量的仓库配置限制；页面来源筛选决定显示哪个平台，不改变账号活动的统计范围。本机任务趋势的时间范围和异常值开关不改变贡献日历。卡片显示账号主页、贡献数、日期范围、统计时区和更新时间；贡献数描述平台账号的可见贡献，不表示全部由 Jarvis 完成。

日历支持鼠标悬停和键盘方向键逐日查看，虚线框表示尚未覆盖，不能作为零贡献日期。部分事件或日期不可确认时显示下限；刷新失败保留同一账号最近一次成功快照并提示过期，身份无法确认时停止展示旧账号数据。刷新交付统计同时请求更新账号活动，页面等待期间仍可使用其他卡片。

页面分别展示以下事实，不把平台账号活动转换为本机 Task / Run：

- 本机运行指标：本机工作台账中的受理、今日/昨日运行、已记录运行总数、已完成运行耗时、平均与中位处理时长、按工作类型拆分的耗时明细和运行趋势；
- 账号贡献日历：GitLab / GitHub 当前登录账号在平台可见范围内的按日贡献；
- Code Delivery Metrics：GitLab 已合并 MR、GitHub 已合并 PR 及代码改动归因证据；
- 任务列表：沿用现有工作项内容、状态、搜索、请求人、分页与选择行为；
- 任务工作台：沿用现有结构、数据和交互，只调整可用宽度与视觉层级。

来源是页面级筛选，选项由已注册来源生成，包括代码平台、工作项平台、消息连接和 Jarvis 运行；`全部来源`不限定平台。它同时限定中央价值证据和工作项范围。`全部`只并列已配置 GitLab / GitHub 的独立证据，不相加 MR 与 PR；未配置统计仓库的代码来源不渲染质量卡片，也不保留空白占位。Jira、禅道、飞书项目、TAPD、云效 Projex、云效 Codeup 和消息连接当前只筛选任务，因为它们的交付结果与人工介入语义不能套用代码交付指标。

任务来源 chip 按 typed subject 的 provider 和对象类型显示：TAPD 工作项显示 `TAPD`，Projex 工作项显示 `云效 Projex`，Codeup 显示 `云效 Codeup 合并请求` 或 `云效 Codeup 提交评论`。平台名称、来源筛选选项和详情外链提示使用同一份服务端 provider 注册信息，最终标签只生成一次。对象类型使用通用显示规则，平台特有的名称由注册信息声明。已注册平台遇到新的对象类型仍保留平台名称；未识别平台显示 `未识别来源（平台标识）`，不归类为 GitLab 或无来源运行。无平台来源的任务显示 `Jarvis 运行`。

Delivery Metrics 卡片由 Status 读模型驱动，不属于下方任务列表本身。基线分析通过普通 `delivery-metrics` lane 任务产出结果；当前执行或等待恢复的这些任务会出现在默认 `jarvis-box tasks list`，历史记录用 `jarvis-box tasks list --all --lane delivery-metrics` 查看；它们也会进入工作项列表，并继续使用统一任务工作台。


## 累计产出与交付质量

本区展示代码托管来源的可审计交付质量、本机运行与工作积累，以及工单自动修复进展。`累计受理记录`、`今日执行次数`、`昨日执行次数`、`累计执行次数`、`累计执行时长`、`日均执行（去异常）`、`平均任务处理时长`、`任务处理时长中位数` 是同一组本机运行指标。`累计执行时长` 来自本机工作台账中已完成运行记录的耗时求和，不代表机器在线时间、代码托管合并历史窗口或已清理后不可观测的其他口径。`日均执行（去异常）` 使用本机工作台账从第一条任务运行到今天的全部日期窗口，不受趋势图时间范围和 `隐藏异常高峰` 控件影响。

耗时记录部分缺失时，已知合计仍展示为 `≥时长`，统计口径说明“部分完成记录缺少耗时，显示已记录耗时下限”；全部耗时未知或账本不能完整读取时显示 `—`，空账本显示 `0秒`。耗时可用性独立于启动次数趋势。

`平均任务处理时长` 和 `任务处理时长中位数` 以单次已结束 Run 为一个样本，与累计执行时长使用相同的运行耗时。成功、失败、停止和取消的运行只要有有效非负耗时均参与统计，零耗时也是样本；进行中的运行和两次运行之间的等待不计入，同一 Task 的多次 Continue 分别计样本。平均值为有效耗时之和除以样本数；中位数取排序后的中间值，样本数为偶数时取中间两值的平均值。统计不剔除异常值，不随来源筛选、趋势时间范围或异常高峰开关变化。

两张耗时卡直接展示有效样本数，部分完成记录缺少耗时时同时说明缺失数量；此时平均值和中位数仅描述已知样本，不加 `≥` 下限符号。无有效样本时显示 `—`，区分暂无完成记录、完成记录均缺少耗时与暂时无法读取统计。

工作类型耗时明细卡最多占交付网格两列，与普通大卡同宽，按 lane 分行展示“工作类型、样本数、平均时长、中位数”，中文名称旁保留原始 lane 标识，避免不同 lane 同名。每行单独说明缺少耗时的数量。历史完成记录未保存 lane 时归入“未记录工作类型”，仍参与总体统计，页面说明历史工作类型缺口；不从任务名称或当前保留任务推测归属。任务记录清理不删除已有工作台账统计。表格在窄卡中可横向滚动，不撑宽整个页面；统计不可读时不保留旧明细冒充当前数据。完整字段与可用性见 [Status API](status-api.md#运行耗时统计)。

工单自动修复进展统一展示 GitLab、GitHub、Jira、禅道、飞书项目、TAPD、云效的全部接入工单，修复代码独立关联 GitLab MR / GitHub PR：`工单受理 → 识别为缺陷 → 进入自动修复 → 提交修复 → 修复已合并`。每层按原工单完整身份去重，图形宽度相对入口数量，百分比用本层已记录数量除以上一层已记录数量；图下展示已记录合并数占受理数的总转化率。图表只展示各阶段数量与转化率，不提供 issue 或 MR/PR 明细展开。漏斗沿纵向排列，各阶段的标签、图形、数量与环节比例在同一行，沿用报告原有结构、圆角与留白。空分母显示 `—`，零计数不绘制有面积的色块。提交/合并尚无已证实记录且修复链接或平台核验存在缺口时，数量显示 `—`，总转化率显示“证据不足”，不能用 0 和 0% 暗示没有交付。最后一层只在平台核验合并后使用绿色。缺失复核结果、修复链接或平台核验时，在统计口径内列出证据缺口数量；未完成 review/CI 与历史缺失均不能算成功。图表标题旁的 ⓘ 显示统计说明，包括证据窗口、任一修复合并、批准与合并的区别及已证实比例的边界。

漏斗历史记录不完整时，已证实的正数以下限符号 ≥ 展示；正数之间仍展示百分比，并在图旁注明按已记录数量计算。各环节比例描述当前已记录数量之间的关系，不能据此推断完整历史的精确转化率。未知的零值与相关转化率显示 —。“是否为缺陷尚未确定”包含未留存及已有处置尚未确定 Bug 的情况，不能一概称为复核结果丢失。记录缺口说明放在统计口径内，不呈现成人工分类待办；读取不会启动分类任务。

漏斗不受页面来源筛选和运行趋势时间范围影响，悬浮身份组件的刷新按钮重新读取漏斗证据。新 workflow 的结构化观察保存在已有工作台账，普通 Task 清理不删除这些观察；历史入口合并平台留存的自动 post-check 回执与已有受理、执行台账，不重新运行分类；旧版保留的 workflow 动作继续计入，确已丢失的复核结果和修复链接显示证据缺口。完整 API 口径见 [工单自动修复进展](status-api.md#自动修复交付漏斗)。

趋势图使用 `/status/api/work-items` 返回的本机工作台账日粒度运行记录。默认展示从第一条本机任务运行当天到今天的全部日期窗口；中间无运行日期显示为 0，第一条运行之前的空白日期不进入图表，也不得由后端固定 7 / 30 / 90 / 180 天滚动截断。时间范围下拉可切换为 `近 7 天`、`近 30 天` 或 `近 90 天`。图表提供 `隐藏异常高峰` toggle，用于剔除异常日后的纵轴缩放；异常值从全量日期窗口的正数日运行量计算，优先使用 `Q3 + 1.5 * IQR` 上界，数据过于集中导致 IQR 为 0 时用 `max(中位数 * 3, 中位数 + 10)` 兜底。toggle 只改变趋势图显示，不改原始计数、不改指标口径；时间范围筛选后仍沿用全量窗口判定出的异常日期。趋势图副标题里的 `日均` 跟随当前时间范围，顶部的 `日均执行（去异常）` 始终使用全量日期窗口。

每日运行折线叠加一条标注为“线性趋势”的虚线，以日期为横轴、每日运行次数为纵轴，使用最小二乘法拟合直线。拟合跟随当前时间范围，包含零运行日期；隐藏异常高峰时，异常日期不参与拟合，其余日期保留原有时间间隔。少于两个可见日期时不绘制趋势线，全零或恒定数据绘制水平趋势线。趋势线只覆盖参与拟合的首末日期，不延伸预测未来；拟合值低于 0 的部分在绘图区边界裁切，不表示负运行次数。趋势线不修改台账、原始折线或 KPI。

每个代码托管来源独立回答三个问题：

1. **当前账号已合并**：当前 `glab` / `gh` 登录账号作为作者创建并已合并的 MR / PR 数量；来源范围内全部已合并数量只作为上下文。
2. **未发现人工纠正**：原样合并，以及发生过修改但未发现符合人工纠正定义的数量与比例。
3. **发现人工纠正**：作者以外的人提出实质性纠错意见，并促成后续代码修改的数量与比例；仅转述机器人意见不计入。

`未发现人工纠正` 与 `发现人工纠正` 使用相同的已知分母。人工 review、comment、approve、merge、rebase 或 committer/pusher 身份本身不能推出人工纠正；运行智能体按判断策略检查公开人类反馈与后续修订的因果关系。

证据覆盖不是价值 KPI。它以“分析覆盖”说明显示：可判断数、unknown 数、仓库覆盖、freshness 和 warning。分母为零、身份归因不足或采集不完整时，两类代码修改数量和比例显示 `—`，明细解释证据不足，不得显示误导性的 0 或 0%。

运行智能体 token 用量不在 Status 页面展示。`runtime_token_usage` 仍作为 API 兼容字段返回，当前 release 恒定是 `status=not_available` 的空壳，页面不把它作为 KPI、成本或模型用量证据渲染，避免未校验的 runtime 归因误导判断。

仓库统计数据在来源质量卡内常驻展示，以“仓库统计”标题和自然高度列表承载。标题旁的 ⓘ 按需显示人工纠正的定义、统计范围与比例分母，不折叠仓库名称或统计结果。其中只展示仓库维度的统计，“未发现人工纠正”同时显示数量与同口径百分比，不列出具体 MR / PR 明细。仓库名称与四项统计在窄卡中分行排列，内容完整显示并推动后续卡片重排。不展示货币 ROI，也不把来源合并记录称为终端业务验收。

来源筛选不改变本机运行指标和趋势；工作台账暂不可读时显示 stale / unavailable 状态，不影响工作项列表继续加载。

## 历史记录分析进度

首次建立基线或仍有 pending 项时，来源卡片显示“正在分析”：

- 当前阶段和 `analysis_progress.lane`；
- `analyzed / total`、待分析数量和进度条；
- 当前 `delivery-metrics` 分析任务对应的仓库与 MR/PR number。

服务端在启动、MR/PR 关闭或合并、分析完成后自动同步交付指标，并每分钟补查；无需打开 `/status`。`discovering_history` 表示正在同步来源历史，`task-running` 表示仍有 MR/PR 等待对应 lane 任务产出，`complete` 表示基线完成。页面接收后台更新通知后重新读取指标和漏斗，手动刷新只更新显示，不启动分析。继续和取消仍在对应任务详情上执行；失败或无效分析不自动重跑。仅当前普通 Task 上已识别的原生智能体容量、用量或上下文中断，才可按有界 Continue 规则恢复，且不会重做历史分析。取消终结该 canonical MR/PR 的分析并投影为最终不可判断，不自动创建替代 Task。

## 工作项与 workbench

“加载更多”请求进行中时不可重复点击；成功后有剩余数据即可继续加载，没有剩余数据则显示“已加载全部”并禁用。读取失败时保留已加载列表并恢复按钮以便重试，无需切换任务来刷新按钮状态。

工作项沿用既有内容和行为：

- 按发起人筛选、任务 / 运行 ID 搜索和分页；
- 工作项完整标题可在列表悬浮提示中查看，所选 Task 的来源图标保留安全来源链接；右侧 Task → Run 树展示 Target 一对多 Task、Task 一对多 Run 的归属。各 Run 展示智能体、状态和开始时间；点击 Run 直接切换查看，点击 Task 查看其最新任务运行。任务历史不再使用两个分离的下拉框，也不显示“更新”时间 chip。刷新保持选择，输出、文件和继续 / 新任务 / 取消操作均绑定所选 Task，不能静默切回最新任务；
- 代码托管任务的仓库、Issue/MR/PR 编号和来源名称来自同一 typed Task subject，外链使用该 Task 的 HTTP(S) target；列表、精确 ID 搜索和详情保持一致，不把缺少旧平铺字段的任务显示成无来源运行；
- 消息连接任务优先用会话展示名作为目标、发送人展示名作为请求人；展示名缺失时保持原有 provider-scoped ID / Task ID 回退，不据名称推断身份；具体渠道由独立 `im_provider` 字段保留，因此展示名不会把“消息连接：飞书 / 企业微信 / 钉钉”退化成通用“消息连接”；
- 服务端 `status_group` 决定状态语义；
- 当前工作只使用同一 TaskView snapshot 的 `active_tasks`；需要处理以 `status_group=needs-human|failed` 为准。磁盘等待显示“等待磁盘空间”，附件确认与交付位置选择显示等待原 IM 用户回复；accepted 等未持有 active Run 的非终态任务单列为等待 / 收尾，完成与取消项进入已完成工作；
- 已识别的原生智能体容量、用量或上下文中断仍属于原任务的 Continue 链。页面显示“自动恢复等待中”、中断原因、下一次自动继续时刻和已尝试次数；等待期间不占用智能体进程，任务列表和任务树同样显示等待状态。达到恢复次数上限或没有可用候选智能体后，任务转为待处理；
- 选中项、安全来源链接、任务 / 运行状态、进度、文件证据与操作策略均来自现有接口。

任务工作台保留现有详情、进度、智能体会话、文件视图、继续 / 开始 / 取消、工作文件夹清理和实时更新。对话、输入及 Task / Run 资料位于独立的对话面板，工作项列表位于其左侧面板，交付成果位于更左侧。四个窗口独立排列；对话的资料栏与输出、输入区分别滚动。

定时认知工作使用统一的人类名称：`memory-consolidation` 为“JARVIS 记忆整理”，`daily-reflection` 为“JARVIS 每日复盘”，`cognitive-evolution` 为“JARVIS 经验积累”。迁移前已落盘任务的 `maintenance` / `self-improve` 在列表与工作台中显示“旧版定时任务”，原始 lane 仅作为审计字段保留；它们不是新建选项。repo-local `self-skills-improve` 不属于该分类。

用户自定义 recurring report 使用固定 `custom-user-task` lane。工作项列表和工作台必须同时显示 lane、`job_id`、触发 `reason`，并在同一 `job_id` 的任务上投影最近成功和最近失败时间。`job_id` 显示为“任务组编号”，`reason` 显示为“本次启动说明”；内置的 `manual-start` 显示为“手动启动”，自定义说明保留原文。最近成功、失败时间属于同组任务的历史结果，在独立分组中分行展示，并说明包含手动和定时启动的任务。缺少时间显示“暂无记录”；这些时间不代表所选任务或所选运行的结果。工作项摘要同样标明“同组任务”，与当前状态区分。`jarvis-command` 表示人工 prompt；`custom-user-task` 表示 operator 创建或宿主定时触发的 providerless prompt job。完成态 `custom-user-task` 的 Start 操作保持 disabled，reason 为 `custom-user-task-rerun-requires-prompt-start`；补跑必须从显式 prompt Start 创建 fresh 任务。

## 三个控件

UI 只消费 response 的 `actions` policy，不在前端重算权限。

| 操作 | 控件 | 请求 |
| --- | --- | --- |
| Start | `新任务` 按钮 | `POST .../start` |
| Continue | `继续` 按钮；必要时启用 agent selector + message input | `POST .../continue` |
| Cancel | `取消` 按钮 | `POST .../cancel` |

交互规则：

- disabled reason 可用于 tooltip/错误提示，但不能通过改按钮名称创造新操作。
- `actions.continue.requires_input=true` 时必须选择智能体并输入新消息；同智能体原生恢复与跨智能体子会话对 UI 都是继续。
- 只有 `actions.continue.enabled=true` 且 `requires_input=true` 时启用 agent selector 和消息输入区；`strategy=recover` 与 `strategy=writeback` 都是 TaskService sealed strategy，不显示 agent selector 或消息输入。
- ChatBridge definite failed/retryable reply delivery 可投影为 `strategy=writeback`。Agent Run 保持 `succeeded`，Task 显示 `needs-attention`；页面从 exact Run typed effect receipt 展示 `succeeded|failed|unknown` 及脱敏的 delivery 信息。`unknown` 不自动重发，Continue(writeback) 只重试同一 Run 的 delivery effect，不重放公开 `reply-error.json`，也不创建新任务运行。
- 需要人工处理的 Run 必须在 Run history row 上第一眼可辨：`state=failed` 或 `state/delivery_state=unknown` 的 Run 带红色「需要处理」标记；IM 附件确认和交付位置选择显示对应的等待用户提示，已裁定的 Run 显示「人工确认：已送到 / 人工确认：没送到」。标记读取该 Run 的最后一条 effect receipt，与 Go 侧 blocker 使用同一判据。
- `actions.continue.attestations` 非空时显示两个裁定按钮「已经送到」「没有送到」，并说明后果不同（送到即收尾，没送到才重投）；列表为空时整条控件隐藏。页面只渲染 policy 列出的值，不自行判定。
- 活动运行的继续操作会在服务端内部停止旧运行后立即继续；用户不需要先执行另一个操作。
- 取消会终结任务；确认文本显示任务 id，不把内部停止运行暴露成并列操作。
- mutation 期间固定控件尺寸并禁用重复提交；完成后从服务端重新读取任务。
- 视图冲突重试耗尽时禁用操作，但不清除用户选中的历史 Run；重新取得有效视图后继续显示同一 Run，不自动跳到 latest。

## 状态词

- 任务：`accepted`、`running`、`finalizing`、`needs-attention`、`completed`、`cancelled`
- 运行：`starting`、`running`、`succeeded`、`failed`、`stopped`
- Monitor：`active`、`finalizing`、`needs-attention`、`completed`、`cancelled`、`recovery-required`、`ci-wait`

人类文案使用“运行需要恢复”或“运行观察链已失联”。低 CPU 或长时间无输出不是失联证据。

## 系统设置

“系统设置”是最右侧的独立窗口。其内容可直接操作，通过拖拽、横向滚动或面板边框键盘定位转向设置，其他窗口保留在空间中。面向设置时，上方悬浮附件提供“重新检查系统”图标。Escape 返回对话并聚焦其键盘定位入口。转向不改变任务或运行；设置内部各分区保留 loading/error，失败不清空上一次成功数据。设置分区按用户要完成的事情组织为：

| 分区 | 回答的问题 | 主要操作 |
| --- | --- | --- |
| 系统概览 | 当前是否可用、是否需要处理、下一步去哪里 | 重新检查、进入对应分区 |
| 处理问题 | 哪个诊断或消息连接有问题，是否需要 Jarvis 处理 | 重新连接、启动显式 operator prompt |
| 工作方式 | 以后新工作使用哪个智能体 | 修改默认智能体、按工作类型覆盖智能体 |
| 接入配置 | 哪些外部来源能进盒子做工，各自还缺什么配置 | 补配置并保存、重启盒子让配置生效 |
| 数据维护 | 哪些终态记录可以安全清理 | 预检、确认清理 |

“接入配置”按来源（GitLab / GitHub / Jira / 禅道 / 飞书项目 / TAPD / 云效 Projex / 云效 Codeup）回答“接上了没有、还缺什么配置、最近有哪些事件被收到后跳过”，并就地提供修改入口。顶部显示支持的外部来源总数及已生效、部分生效、未生效数量；“通用设置”独立列出，不计入外部来源数量。来源目录显示名称和接入状态，点击只显示对应配置，切换与刷新保留未保存输入。保存只清空当前来源已提交的密钥输入，其他来源的草稿保留。保存与重启结果始终可见。目录支持方向键、Home、End 和单个 Tab 停靠点；桌面目录位于详情旁，窄屏目录换行排列在详情上方。

每个来源的状态必须三态可分——“未生效”（接入本身还没配完）、“部分生效”（接上了，但有关键项在吃代码里的默认值，行为已被收窄）、“已生效”。把“用默认值”显示成“已设置”，正是这类问题在页面上完全看不出来的原因。来源的接入与否沿用服务装配与 `/health` 的同一份判据，不另写一套。每个来源同时列出没处理的事件和人话原因，英文枚举不得直出，并带出操作员要抄进白名单的那个稳定取值（Jira 的类型 ID 挨着类型显示名显示——显示名跟着触发者的语言走，ID 不跟）。凭证字段只显示“已配置 / 未配置”，值不进浏览器 response；替换凭证时重新填一次，输入框永不回填，留空表示这次不动它。

保存写进 `JARVIS_ENV_FILE` 指向的环境变量文件，从下一次启动开始生效，因此**“现在”这一列永远是此刻真正在生效的值**——刚保存完的那几行看起来没变是对的，页面必须说清这是为什么，否则操作员会以为自己没保存成功。写接口只接受一张从键目派生出来的白名单里的键（不是黑名单：这个文件会被服务管理器 source，写一个键就是往受监管进程注入一个环境变量），拒绝控制字符与首尾空白，服务地址还拒绝用户名、密码、查询参数和片段，并在保存前拦下会让盒子起不来的跨键约束（评审范围必须是可见范围的一部分；启用 TAPD 时需有 API Token 或 API 用户与密码，且须有 CLI 可用的个人令牌（或 `TAPD_API_TOKEN`）；启用云效时需有 API 地址、组织编号和访问令牌）。保存前必须先备份一份，面板把回滚命令和解析后的真实路径一起给出。保存前不重跑完整启动检查，这句话要在面板上说清楚，不能让人以为按下去就是一次启动预演。

重启能力必须由读接口在用户点之前就发下来：能重启的给按钮，容器编排管理的盒子**必须拒绝**而不是回退到 `launchctl`/`systemctl` 分支上去报一个假成功。重启会打断正在运行的智能体，而且浏览器活不过重启，所以“重启后自动接着跑”这件事在面板上做不到——页面必须直说，不得让操作员以为等一会儿什么都会自己回来。做不到的是**自动**续跑，不是续跑本身：确认重启之后那几条运行必须先被干净地中断并留下收据（与 CLI 的 `stop`/`restart --force` 走同一条路，收据就是工作项页面上「继续」按钮的唯一依据），再交给服务管理器。少了这一步，重启就是把运行连同进程一起抹掉，而页面上看不出任何区别。重启后页面自行轮询直到盒子重新应答；只有先观察到它断过，后面的应答才算数。

版本、环境、路径、进程/容器资源和内部轮询统一收进系统概览底部的“技术细节”。它们用于确认部署和排障，不作为顶层任务，也不得把容器视角资源写成 Docker 宿主机全局资源。技术细节、版本浮层、tooltip、title 和 aria label 也属于 Status UI：标签、状态值、布尔值、定时提示、版本字段、收件人模式和已知来源/连接器枚举必须使用中文产品语言，不直出 `enabled`、`disabled`、`ready`、`running`、`next`、`Commit`、`Version`、`trigger_author` 等 API 原值。

“授权”面板同样默认收在“技术细节”里，显示本机授权身份与租约：安装 ID、机器标识、是否已激活、判定、策略版本、授权 ID、类型、授权方式（仅离线授权显示）、租约截止、合同截止（仅在线授权显示——离线授权的租约截止就是合同上的那一天，同一份文件的同一个日期不画两行）、最早可激活、是否已停用、时钟状态、最近签到、版本提示。“机器标识”一行显示本机读到的宿主标识与它的来源（启动器写入的文件 / 机器固件）；读不到时显示“读不到”并说明后果——新的任务运行 不会开工，要重新用官方安装脚本或启动器部署。这一行要显示出来，是因为一台被拒的机器上，运维第一个要回答的问题就是“它认为自己是哪台机器”；它同时也是 `run_allowed` 说“否”而其余各项都正常时唯一的线索。它的字段与 `jarvis-box license status` 是同一张表，使用中文产品语言（不直出 `ALLOW`、`DENY`、`PAID`、`TRIAL`、`generation` 等 API 原值）；本机不受授权约束时，面板显示“本机不受授权约束（开发构建未配 JARVIS_LICENSE_URL），不会限制任务运行”，而不是显示成已授权。

两种情况会把授权面板提到系统概览第一层，并在面板顶部显示服务端给出的一句原文：本机当前不能创建新的任务运行（未激活、已停用、判定非允许、租约过期、时钟不可信等任一条），或最近一次签到失败。概览结论同时提示“授权需要处理”；授权面板在“处理问题”中也显示相同原因。任务问题数量仍只统计需要处理的任务。其余情况下授权不占问题数，系统结论仍由健康检查、任务存储和消息接入决定；授权未配置不构成问题。

“签到失败”一行显示规范化后的原因（服务端业务码对应的中文，或“没能完成签到请求”）与失败时刻，只在失败晚于最后一次成功签到时出现：授权服务返回错误、连接失败和请求超时都算签到失败，本机自己的前提不成立（尚未激活、已停用）也算一次并照实说是本机的原因，不写成网络或本机读写问题，一次成功签到之后该行自动消失，不需要人工清除。激活、重新激活或导入授权后，已被当前验签状态否定的“尚未激活／已停用”旧失败不再作为当前问题；离线授权不显示旧在线签到故障。真实网络或服务端故障仍需签到成功才能清除。系统设置顶部“重新检查”会先通过当前授权客户端执行一次检查，再重读各分区；在线授权发起签到，离线授权只做本地验签。忙碌期间重复点击合并到同一轮，只补跑状态读取，不重复签到。授权服务不可达时页面不得显示“系统当前可用”。SSE 只发送问题与到期提醒，完整身份字段由系统设置的授权只读接口获取；事件更新保留展开详情和键盘焦点。

“到期提醒”一行与悬浮身份组件的版本号旁边那一格说的是同一件事：还有 7 天（含）以内就要失去授权，或者已经失去了。判据由服务端算一次、两处共用：离线授权看租约截止，在线授权看合同截止——在线租约按小时滚动续签，拿它当判据会让每一台健康机器常亮。剩余天数向上取整，剩 6 天 5 小时说“授权 7 天后到期”，宁可早一天说；过了那一天说“授权已到期”。悬浮身份组件中的提醒用琥珀色（快到期）与红色（已到期）区分，但颜色不是唯一语义：完整那句（日期，和该找谁——离线是服务商重新签发授权文件，在线是续签合同）在悬停与键盘 focus 的气泡里读得到，也在“授权”面板的这一行里读得到。它不占问题数、不把面板提到顶层，也不参与 Run 门——快到期时这台机器还能照常干活，把一条提醒渲染成一次故障，运维会去追一个不存在的问题。本机未激活、已停用或日期为零值时不出现这一行，也不画那一格。

“版本提示”一行显示服务端给的那句升级建议（当前版本在版本目录里是什么档位、建议升到哪一版）和一条说明链接。它不占问题数、不把面板提到顶层：这台机器现在能照常干活，只是有个更新的版本，而把一条建议渲染成一次故障，运维会去追一个不存在的问题。它跟着每次验签通过的激活/签到刷新，停用后消失。本机版本在服务端目录里没有登记时不显示这一行（目录是手工维护的，刚发出去的版本会落在这里），也不显示成“不再支持”。

“工作方式”中的“模型资源与额度”按每个有效调用入口显示四段调用链 `智能体 → 目标模型 → 计费方 / 账户 → 额度证据`，不得把额度直接归因给智能体名称。相同 `account_ref` 表示多个智能体共享同一计费账号；页面在各自调用链中重复该脱敏引用，让共享关系可以直接比较，但不把余额或 token 作为累计产出 KPI。Codex 使用 ChatGPT 登录时展示套餐和滚动额度周期；任一支持的智能体通过 `api.deepseek.com` 路由时展示对应有效凭据的 DeepSeek 钱包余额。没有安全、公开额度接口的计费方仍显示已识别的模型和计费方，并明确标记“暂不支持自动读取”，不得把未知状态显示成可用。

Codex 的调用链按本机 `config.toml`、选中的 profile 和当前入口的 CLI overrides 解析实际 `model_provider`、模型、网关与凭据引用。不同工作类型的 prefix args 必须独立求值，不能复用默认 Codex 入口的计费账号。配置无法可靠解析时显示“Codex 接入方式待确认”及明确原因，不回退成 ChatGPT/OpenAI 路由，也不执行 provider 的命令型认证配置。

额度状态与智能体命令可用性是两个独立事实：命令可用不代表计费账号有余额，额度读取失败也不阻断已有任务。手动“重新检查”会重新读取额度；页面只显示脱敏账户引用、规范化余额/窗口和采集时间，不显示邮箱、token、原始上游错误或响应正文。

每个修改操作都写明何时使用、影响当前还是未来工作、是否中断、是否可恢复、成功证据和失败后的下一步。修改默认智能体与工作类型覆盖只影响保存后新启动的运行；正在运行的智能体不切换。重新连接只短暂重建消息接入，不取消已有任务/运行。连接控制器不可用时明确提示“消息连接当前不可用，无法重新连接”，不会显示为已重连。operator prompt 创建可在 Status 工作项中跟踪的新任务/运行。终态清理不可恢复，但不处理活动任务、正在运行的智能体、服务日志或依赖缓存。

所有 mutation 使用服务端现有 owner，不做 optimistic update，完成后重新读取真实状态。operator prompt 成功后只从 typed receipt 的 `TaskView.task_id`、`RunView.run_id` 和 status 显示成功证据，不读取旧的平铺字段，也不把创建成功投影成未知模式。页面读到系统状态之前一律不开放状态变更：变更控件禁用并写明原因，只留查看和无副作用预检（`tasks/clean?dry_run=1`）。控件的 disabled state 必须与 API 能力一致，不能提供注定返回 403 的假入口。

该面板允许展示当前部署的主机路径和已脱敏配置，但不显示 provider credential、private resume handle、raw inbound payload、native AgentSession 或未脱敏 service/runtime log。系统设置面板与其他 `/status` 功能属于同一可信团队边界；唯一例外是 Task 文件内容和已登记 Workspace 浏览，它们只接受 loopback 请求，不能依赖上游网关替代本机边界。其他系统设置的更强认证仍由上游网关负责。

## 视觉与无障碍

- 悬浮身份组件是页面中唯一的数字员工身份标题；本机运行指标位于交付成果窗口，来源和按发起人筛选位于工作项窗口的工具栏。
- 系统设置是持久窗口，Escape 转回对话，焦点不会被关在一处。面板内容自身滚动，不与对话产生双重滚动。
- 四个窗口从左到右为交付成果、工作项、对话、系统设置。面向哪个窗口，哪个窗口来到正前方；其余窗口保留周边的空间位置。工作项列表独立滚动，工具栏保持可见，分类标题随列表内容滚动。
- 采用跟随视角的摄影背景、烟灰色磨砂材质、柔和阴影与细亮边。前后关系由透视、遮挡和留白表达，正文保持稳定对齐和清晰对比度。
- 任务分组与选中标签使用中性的半透明底色，组内标题与文件阅读区域延续面板材质。当前任务和运行保留明确的文字标识；任务树使用紧凑缩进，系统操作列表使用共享底色与行间分隔。
- 语义颜色只表达状态，不作为唯一识别方式；id、时间和日志使用等宽字体。
- 控件有键盘焦点、disabled state 和至少 WCAG AA 对比度；支持 reduced motion。
- 页面按桌面工作台设计；正面窗口保持可读，周边窗口可部分进入视野，页面不产生水平滚动。
- 来源与仓库文本只通过 `textContent` 写入；价值区不展示具体 MR / PR 外链。

任务与运行树直接展示真实 Task ID 和 Run ID，不以 R1/R2 替代运行身份。每行提供独立的复制 ID 图标，复制不改变当前选择。任务上下文与任务树位于对话侧栏，长内容自动换行，树内不重复展示 ID chip。

工作文件夹使用常驻展开的目标级列表，不使用 chip。直接汇总当前 Target 下各 Task 的工作目录，显示未清理数量、完整路径、所属任务及清理可用状态；部分读取失败必须明确显示，不能冒充完整数量。清理动作绑定工作文件夹所属 Task，不随当前 Run 选择改变。

Status 桌面主区域为环绕用户的四个窗口。工作项窗口独立展示列表；对话窗口左侧显示运行进展、输出、文件与输入操作，右侧显示所选任务资料。来源、请求人与搜索位于工作项工具栏。默认智能体、有效模型、推理级别与工作状态位于悬浮身份组件。任务资料仍按 Task 分组展示工作文件夹与运行历史。

身份、执行配置、运行状态、版本与全局刷新组成正前方窗口上方的悬浮玻璃附件，与窗口共用空间坐标和光照，不固定在屏幕边缘。交付成果拥有八项本机指标，四个窗口共享中性玻璃材质与系统字体。环境、色彩、空间和组件规格见[设计系统](../DESIGN.md)。

运行进展位于对话上方，默认收起，展开后以横向事件序列呈现，可独立滚动；同一工作项内刷新保留展开状态。输出采用消息身份与时间在上、正文在下的阅读结构；用户和智能体正文使用产品字体，工具与代码使用等宽字体。查看模式、消息筛选、滚动和跟随状态在一行内分组排列；输入区统一边框，继续执行使用主操作色。文件视图保留原有只读浏览与预览行为。

单选下拉框在鼠标悬停后自动展开，移开时延迟关闭，允许移入菜单选择；悬停不改变选中值。点击、触控和键盘仍可操作，方向键选择、Enter / 空格确认、Escape 取消、Tab 离开；禁用控件不展开。菜单位于顶层，不受空间面板裁切，确认时沿用原控件的变化事件与操作策略。

桌面控件以 36px 高度为主，紧凑工具栏采用 32px；所有窗口内容均可直接操作，面板边框可聚焦后使用键盘转向。使用单一系统 sans 字体，ID 与代码使用等宽字体，辅助文字保持 AA 对比度。长 ID、路径和输出可以查看完整内容。面板边框与设置分区都支持方向键操作。

来源切换加载期间继续编辑搜索，页面会重新读取当前筛选范围，不能因丢弃旧响应而停留在空列表。工作文件夹列表刷新时保留已显示的路径，读取完成后再替换，避免展开时闪回加载占位。清理成功后先刷新当前视图，再读取各任务的工作文件夹；因选择或视图更新而失效的旧读取不显示为失败，真实读取失败仍提供重试。清理其他任务的文件夹不改变当前所选任务与运行。

页面采用四个持久窗口的环绕布局，以同一空间的旋转模拟视线转向。窗口共享悬浮身份组件和统一磨砂材质，八项本机运行指标属于交付成果面板。工作项与对话共同保留 Target → Task → Run 选择、真实 ID 复制、运行时间与 Task 工作文件夹语义。

视觉层级：交付报告在最左侧窗口独立阅读，工作项列表位于中间偏左，对话及任务资料位于其右侧。工作项标题和对话正文 15px、任务分组标题 12–13px、元数据 11px。任务树按创建时间倒序展示 Task，各 Task 内按开始时间倒序展示 Run；Task 同时间按 ID 稳定排序，Run 同时间按序号和 ID 稳定排序。任务树随内容自然撑开，对话面板右侧的任务资料区域统一滚动，不为工作标题保留额外行；同一工作项内切换或更新任务与运行时保留任务资料区域的滚动位置。工作文件夹路径列表随内容撑开；仅 detail-resources 设置滚动，内部任务树和目录列表不设置独立滚动；系统设置与文件视图共享同一组中性 token。

组件适配：Message 使用右对齐的浅色用户气泡与无背景助手正文，工具输出使用独立圆角容器。面板使用中性玻璃材质、柔和阴影与 32px 圆角；原有输出 / 文件与消息筛选仍位于对话内部。Prompt Input 将文本输入放在整体容器上方，智能体选择和现有新任务 / 继续 / 取消操作放在下方；保留原键盘提交、disabled 及权限行为。原生 DOM 适配不引入第二个业务状态所有者，组件来源与 MIT 许可保留在样式源码中。减少动态效果时，窗口与背景直接跟随目标视角。

Status 采用单一磨砂外观，不提供深浅主题切换，不读取旧的浏览器主题选择或跟随系统明暗变化。面板、原生控件、图表、状态色、消息、输入区与设置面板采用协调的中性配色；减少透明效果时主要阅读平面改用不透明底色。

交互打磨遵循 UI Skills 的 better-ui / better-accessibility / better-layout：正文与玻璃背衬分层，背景模糊不影响正文清晰度；助手正文不保留旧消息卡片阴影；树形控件内外圆角按间距协调；触控输入使用 16px 字号，减少动态效果时禁用按钮按压缩放。

运行趋势按实际容器宽高绘制，坐标文字固定为 11px，绘图区保留报告原有高度；密集日期缩小普通数据点，保留异常点与真实日期/次数提示。运行进展采用连接线与节点构成的横向时间线，末节点以实心标记最近事件，不推断成功状态。详情资源在所有宽度下按 Task 分组，工作文件夹位于所属 Task 的运行历史上方。当前 Task 默认展开，其他 Task 显示摘要，支持独立展开和同时比较多组；分组内部随内容撑开，由 detail-resources 统一滚动；Task 分组标题随内容滚动，不使用粘性定位。目录展示标签、完整路径和可清理状态，提供复制路径、查看文件及清理操作；查看文件定位对应 Task 的目录，清理确认明确所属 Task 与路径。历史 Run 的选择不改变目录归属，工作文件夹表示 Task 当前目录，不代表历史快照。

任务记录使用明确的视觉层级：每个 Task 以受理时间作为阅读标题，真实 ID 保留在辅助行并可复制；当前查看的 Task 用边框和文字标记区分，Run 仅用文字标记区分，选中行不增加底色，不使用阴影。工作文件夹和运行历史使用独立小标题，两组列表与各自标题齐平，不添加树线或额外缩进；Task 标题的左右内边距为零，间距由分组布局控制。Run 优先显示智能体、状态和时间，真实 Run ID 放在次行。来源与请求人筛选在宽度允许时并排，较窄列表中各占一行，搜索单独占一行。

交付面板以混合尺寸卡片展示交付质量与本机运行积累，工作项和对话面板承载所选任务与运行。工作文件夹随所属 Task 分组展开，以轻量分隔和自然高度列表作为辅助资料；时间线标题使用“本次运行”，指向任务树中选中的真实 Run。工作项及同一目标的主任务按受理时间、Run 创建/开始/完成时间和交付 effect 完成时间的最新值排序，资源维护导致的 Task updated_at 变化不参与排序；持久化时间不被改写。

通过精确编号定位的 Task 即使不在当前已加载的工作项页中，也可以继续切换其 Run、查看对应输出和文件；当前页的分页范围不改变已选 Task 或 Run 的归属。读取和操作仍受当前视图版本与身份校验约束。

## 能力清单

`/test-coverage` 按业务场景列出功能要求名称、稳定编号和已登记的实现缺口，支持搜索及场景定位。页面沿用中性配色、字体与控件，独立跟随系统明暗主题，不加载工作台的场景与磨砂布局。目录数量不表示产品完备率或验收通过率。

页面尚未接入实际验收记录，功能条目统一显示“未验证”；这表示页面没有可核对的执行证据，不表示该功能失败或尚未实现。已登记的实现缺口另行展示。页面不提供通过率、执行结果筛选或用例证据详情。

业务验收须核对匹配版本、部署、平台及声明范围的实际运行记录和外部结果。一个正常流程通过不能使其他条件、平台或整个父场景自动完成。源码关联、测试函数和组件检查成功不能产生业务通过状态。

页面不在线执行测试，也不展示凭据、私有会话、原始源码或主机私有路径。清单读取失败时显示错误并允许重新加载。

## 文案与操作说明

交付成果的 KPI、仓库统计和自动修复图表通过标题旁的 ⓘ 提供次要说明。点击或使用 Enter、空格打开，点击外部、关闭按钮或 Esc 关闭；浮层可独立滚动。打开与关闭不改变视角，后台统计更新保留仍存在的说明与阅读位置。数据不完整、读取失败和统计关闭等重要提示继续直接展示。

页面使用简短、具体的中文描述状态和动作；提示、按钮、悬浮说明与可访问名称保持一致。用户指令、代码、路径和原始日志保留原文，已知会话事件在标题中显示为“回复”“命令执行”“已完成”等中文说明。

“接入配置”区分“缺少配置”“部分配置待确认”“配置齐全”。这些状态反映配置检查结果，不代表已验证平台连接或通知送达。配置表的“当前生效值”显示正在运行的配置，“修改为”用于填写下次启动使用的值。保存不影响运行中的任务；重启会中断执行，服务恢复后需到对应任务中选择“继续”。密钥输入框留空保留原值，填写后仍须保存并按提示重启。

“预览清理范围”不删除数据；“永久清理记录”仅删除超过保留期限、已结束且工作文件夹已清理的任务记录。工作文件夹清理同样提示删除后无法恢复。结果是否送达尚不明确时，需先在接收方核实，再选择“确认已送达”或“确认未送达”；后者会重新发送本次结果。

## 阅读提示

首次操作指引说明交付成果、工作项、对话和系统设置的用途，以及拖拽、横向滑动和纵向滚轮操作；“关闭指引”仅关闭提示，不启动任务。

对话中的完整运行契约追加段落默认收进“运行环境说明”，匹配的历史文件与交付说明也可在其中展开。完整原文始终保留，无法识别或不完整的格式继续直接显示；智能体回复不折叠。说明展开后，输出更新保留阅读状态。

普通设置常驻必要的影响说明，保存或连接结果显示在操作反馈中。删除、重启等操作继续直接说明重要影响。交付面板用主要 KPI 的字号和底色突出今日、累计执行次数；来源卡的统计起点、历史更新时间和地址可在来源标题旁的说明中查看，各项统计口径保持独立。
